# Analysis QA

The active numbered analysis scripts write compact checks to `outputs/<producer>/`. The folder name starts with the script number, so each result can be traced without guessing which analysis step created it.

`qa_products.csv` is the source of truth for QA provenance. It records every expected result, its producer, and whether a complete rebuild must create it. The cache-contract result is required; the TerraClimate missing-site table is always refreshed but remains optional because zero missing sites is valid.

Run the provenance check after rebuilding the analysis:

```powershell
Rscript 09_analysis/qa/scripts/validate_qa_products.R --require-outputs
```

The check fails when:

- a registered producer is missing or is not tracked by Git;
- a producer does not name the result it is supposed to create;
- an unregistered result appears in `qa/outputs/`; or
- a required result is absent when `--require-outputs` is used.

QA files are generated results. The scripts, manifest, tests, and directory structure are tracked; the CSV outputs can be regenerated on a new server. Row-level analysis data remain in `../data/`, and the one authoritative model result remains in the directory named by `../results/model_runs/README.md`.

## Seedling spatial support

`scripts/audit_seedling_spatial_support.R` checks the spatial-grain question raised by the preliminary seedling results. FIA seedling tallies carry both a condition ID and a numbered microplot/subplot location. The script confirms those assignments, distinguishes eligible condition microplots from microplots that contain seedlings, and measures how often verified agent-attributed deaths occur on those same numbered subplots. It also reports starting seedling abundance, richness, niche coverage, and microplot support for the modeled histories.

The same producer also reports how many modeled endpoints use `PLOT.MANUAL < 2` and conservatively refits the seedling models using only histories with manual version 2 or later at both endpoints. This addresses the older national tally rule under which a calculated value of six could mean "six or more." Some FIA regions collected exact counts under older manuals, so this restriction is a diagnostic rather than a proposed production filter.

This is a diagnostic of condition-wide disturbance predictors paired with microplot seedling observations. It does not change the condition-level model or reinterpret absence of a seedling record as a missing survey.

`scripts/run_seedling_subplot_mortality_sensitivity.R` rebuilds the cumulative mortality risk set while retaining tree subplot. It restricts both the denominator and agent-death numerator to the union of numbered subplots that contain seedlings at the first or final endpoint. The script first checks that its unrestricted reconstruction reproduces the production mortality product, then refits the seedling models on identical rows using condition-wide and subplot-restricted mortality.

Run the three seedling checks in this order:

```powershell
Rscript 09_analysis/qa/scripts/audit_seedling_spatial_support.R
Rscript 09_analysis/qa/scripts/run_seedling_support_robustness.R
Rscript 09_analysis/qa/scripts/run_seedling_subplot_mortality_sensitivity.R
```

`scripts/run_seedling_support_robustness.R` uses the history-level support table from the first script. It tests initial seedling tally, initial species richness, eligible microplots, and microplots containing seedlings one at a time. Each model keeps the seedling histories fixed and tests whether the fire, insect, or disease relationship changes with that support measure. These retained QA results document why seedlings are excluded from the active models.

These seedling outputs are optional because they document an already-resolved modeling decision and are not regenerated by the active sapling-and-adult pipeline. Run the three commands above whenever that decision needs to be audited again. Their absence does not make a clean active-analysis run fail the required-output check.

## Cross-machine consistency

`collect_consistency_snapshot.R` creates canonical content hashes, climate-year fingerprints, sample counts, schemas, and environment metadata outside the repository. When a snapshot differs, `diagnose_consistency_differences.R` narrows it by keyed column and state. Always pass an output directory under the operating system temporary directory; these machine-specific audit files are evidence and are not repository products.
